# Claude Code plugin facts this design relies on

Checked 2026-10-24 against the official Claude Code documentation (code.claude.com). Each fact
names its source page. "Unverified" means the docs did not settle it, and the dependent step uses
the named fallback.

| # | Fact | Source | Consequence for this repo |
|---|---|---|---|
| 1 | Marketplace `archive` source (zip over HTTPS) is supported from **Claude Code 2.1.224**. | [marketplace-reference#archive-plugin-source](https://code.claude.com/docs/en/plugins/marketplace-reference.md#archive-plugin-source) | Minimum version in the README (AC-10, AC-19). |
| 2 | An installed plugin's version is taken from **`plugin.json` `version` first**, then the marketplace entry's `version`, then (for an archive) the archive's SHA-256. Users "stay on their cached copy until the string changes". | [loading#how-claude-code-computes-the-version](https://code.claude.com/docs/en/plugins/loading.md#how-claude-code-computes-the-version), [host-marketplace#release-a-new-version](https://code.claude.com/docs/en/plugins/host-marketplace.md#release-a-new-version) | Stamping the tag into `plugin.json` per release (AC-3) is what makes each release an update. The `0.0.0` placeholder must never ship. |
| 3 | Marketplace **auto-update is off by default for third-party marketplaces**. Switch it on in a session with `/plugin` → *Marketplaces* → select the marketplace → *Enable auto-update*. Admins can set `autoUpdate` on an `extraKnownMarketplaces` entry. No CLI flag was found. | [install#turn-auto-update-on-or-off-for-a-marketplace](https://code.claude.com/docs/en/plugins/install.md#turn-auto-update-on-or-off-for-a-marketplace), [loading#which-marketplaces-and-plugins-auto-update](https://code.claude.com/docs/en/plugins/loading.md#which-marketplaces-and-plugins-auto-update) | The README procedure for AC-12. |
| 4 | Auto-update does **not** run at session start. In an interactive session it runs after the first message, after a random delay of up to ten minutes. `DISABLE_AUTOUPDATER`, `DISABLE_UPDATES` and `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` turn it off. | [loading#when-auto-update-runs](https://code.claude.com/docs/en/plugins/loading.md#when-auto-update-runs) | AC-12's "two session starts" means two sessions that each stayed open past the update pass. The notify hook can fire in the same session that later updates itself; its message says it can be ignored when auto-update is on. |
| 5 | A hook entry takes `timeout` in **seconds**. The default is 600 for command hooks. | [hooks](https://code.claude.com/docs/en/hooks.md) | `hooks.json` sets `"timeout": 5` on both SessionStart entries (AC-13). |
| 6 | SessionStart can return `hookSpecificOutput.additionalContext`, which is added to Claude's context. `systemMessage` is a universal output field shown to the user. Matchers: `startup`, `resume`, `clear`, `compact`. | [hooks](https://code.claude.com/docs/en/hooks.md) | AC-15's rules pointer is **kept**. Both SessionStart hooks match `startup` only. |
| 7 | `${CLAUDE_PLUGIN_DATA}` exists. It resolves to `~/.claude/plugins/data/<id>/`, is created on first reference and is kept across plugin updates. `${CLAUDE_PLUGIN_ROOT}` is the installed version's directory and changes on every update ("don't write state there"). | [manifest-reference#environment-variables](https://code.claude.com/docs/en/plugins/manifest-reference.md#environment-variables) | Hook caches go to `${CLAUDE_PLUGIN_DATA}` (AC-13, AC-15). |
| 8 | Manifest **`userConfig`** exists (string/number/boolean/directory/file, optionally sensitive). `${user_config.KEY}` is substituted in MCP server config, including `env`. Not in shell-form hook commands. | [manifest-reference#user-configuration](https://code.claude.com/docs/en/plugins/manifest-reference.md#user-configuration) | AC-17 uses `userConfig` (`tsenv_path`, type `file`, optional). It feeds a **separate** variable, `TESTSTAND_MCP_TestStand__PluginEnvironmentPath`, so an empty plugin value can never hide a machine-wide `TestStand:EnvironmentPath` (setx or `appsettings.json`). The server uses the plugin value only when it is non-blank and not an unexpanded `${…}` placeholder. What Claude Code substitutes for an *unset* optional key is **unverified**, which is why the guard exists. The AC-10 install check records the observed value. |
| 9 | MCP server **start** timeout: `MCP_TIMEOUT`, default **30 000 ms**. | [env-vars](https://code.claude.com/docs/en/env-vars.md) | Start budget for AC-2 = 15 s. Measured cold start of the chosen layout: 0.4 s. |
| 10 | On Windows a shell-form hook command runs in **Git Bash if present, otherwise PowerShell**. A hook can pin `"shell": "bash"` or `"shell": "powershell"`. Git Bash is not required. "Without Git Bash, a shell-form hook with no `shell` set runs in PowerShell, where it can fail", and "a hook that can't start is a non-blocking error", which shows a `<hook name> hook error` notice in the transcript. The docs do not say what a `"shell": "bash"` entry does on Windows when Git Bash is absent (**unverified**, and not observable on this station, which has Git Bash). | [hooks](https://code.claude.com/docs/en/hooks.md) (command hook fields, exec form and shell form, failed hooks on Windows without Git Bash) | A `sh …` command can fail on a station without Git Bash. Slice 4 pins `"shell": "powershell"` for every Windows hook and does **not wire** `platform-guard.sh`: an unpinned entry would run in PowerShell and a pinned `bash` entry has no documented outcome, so either could show a hook-error notice to a Windows user. The file and its tests stay; the non-Windows message is therefore not delivered at run time. |
| 11 | A PreToolUse `allow` does **not** override the user's own `deny` or `ask` rules. Across hooks, precedence is deny > defer > ask > allow. | [hooks](https://code.claude.com/docs/en/hooks.md), [permissions](https://code.claude.com/docs/en/permissions.md) | The auto-allow hook can never widen what a user has denied, which is a safety property of AC-14. |
| 12 | Tools of a plugin-bundled MCP server are named `mcp__plugin_<plugin>_<server>__<tool>`. | [mcp](https://code.claude.com/docs/en/mcp.md), [plugins/components#mcp-servers](https://code.claude.com/docs/en/plugins/components.md#mcp-servers) | Prefix `mcp__plugin_teststand-mcp_teststand__`, derived in `build/PluginIdentity.psm1`. |
| 13 | `CLAUDE_CONFIG_DIR` relocates every `~/.claude` path, and settings are read from `$CLAUDE_CONFIG_DIR/settings.json`. Whether `~/.claude.json` (user-scope MCP servers) moves too is **unverified**. | [claude-directory](https://code.claude.com/docs/en/claude-directory.md) | The AC-10 clean-profile check confirms `claude mcp list` shows **no** `teststand` inside the isolated profile before installing. Fallback: a second Windows user. |
| 14 | Plugin updates install into a new `cache/<marketplace>/<plugin>/<version>/` directory. The old one is kept, so a running session keeps using it until `/reload-plugins`. Old versions are removed about 14 days later. | [loading#find-plugins-on-disk](https://code.claude.com/docs/en/plugins/loading.md#find-plugins-on-disk) | A plugin update never overwrites a running server's exe. The "update while running" risk is closed. |
| 15 | On Windows **without** Git Bash, a shell-form `PreToolUse` or `PermissionRequest` command hook that fails or times out with `onFailure` unset can **block the tool call**: "only exit code 0 or 2 counts as this hook's verdict". `"onFailure": "continue"` lets the call go ahead when the hook fails; it needs Claude Code **v2.1.295** or later. | [hooks#failed-hooks-on-windows-without-git-bash](https://code.claude.com/docs/en/hooks.md) | `allow-readonly.ps1` exits 0 on every input, so only a failure to start PowerShell (a locked-down station, a timeout) can block a read-only call. `hooks.json` does not carry `onFailure` yet: it is newer than the 2.1.224 minimum of fact 1, and no doc says an older client ignores an unknown field. Open for the maintainer. |
| 16 | A hook `matcher` made only of letters, digits, `_`, `-`, spaces, `,` and `\|` is an **exact string, or a list of exact strings** separated by `\|` or `,`. Any other character makes it an unanchored JavaScript regular expression. | [hooks#matcher-patterns](https://code.claude.com/docs/en/hooks.md) | The PreToolUse matcher is the `\|`-joined list of the full allow-listed tool names (all characters are in the exact-string set), so it matches those names and nothing else. |
| 17 | A plugin's `hooks/hooks.json` wraps the event map in a top-level `"hooks"` key and accepts an optional top-level `description`. A command hook with `args` runs in **exec form**: `command` is spawned directly as an executable (`powershell.exe` qualifies) and each `args` element is one argument with no quoting, and `shell` is ignored. | [hooks](https://code.claude.com/docs/en/hooks.md) (plugin hooks, exec form and shell form), [plugins/components#hooks](https://code.claude.com/docs/en/plugins/components.md) | `hooks.json` uses the shell form with `"shell": "powershell"` and quoted `${CLAUDE_PLUGIN_ROOT}` paths, as planned. Measured on this station: ~0.6 s per auto-allowed call (an outer and an inner PowerShell start). The exec form (`"command": "powershell.exe"`, `"args": ["-NoProfile", "-ExecutionPolicy", "Bypass", "-File", "${CLAUDE_PLUGIN_ROOT}/hooks/..."]`) would save one start and needs no path quoting; it is not used because the plan and the settled decision pin the shell form. |

## Also found on this station

- **No PowerShell 7.** Only Windows PowerShell 5.1 is installed, so the build scripts target 5.1
  (the planned `#Requires -Version 7` is dropped). The zip is written with explicit forward-slash
  entry names, which is the reason 7 was required.
